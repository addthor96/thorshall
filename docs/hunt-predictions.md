# Hunt predictions

The public `/bonus-hunt` page accepts free end-balance guesses while its active hunt is collecting bonuses and predictions are open. Compact selectable hunt cards appear at the top; the prediction section and full bonus breakdown below both follow the selected card. It shows 1st, 2nd and 3rd place without prize amounts; completed hunts rank guesses by absolute distance from the displayed final end balance, with earlier final saved guesses winning ties.

## Current identity and entry rules

- Viewers must sign in with Twitch before submitting. The server derives their Twitch user ID and login; a typed username cannot claim another account.
- One prediction per stable Twitch account ID for each hunt, across browsers and Twitch name changes. This limits accounts, not necessarily people with multiple accounts. Existing unverified historical entries remain separate and never claim ownership of a Twitch account.
- No email permission, purchase, deposit or payment is requested.
- Each eligible username and saved prediction appears in the public list as soon as it is accepted. The viewer's own saved amount is shown separately after Twitch sign-in, with Change prediction, Save changes and Cancel controls while entries are open. An edit replaces that account's current guess, including across browsers and Twitch name changes. Final top-three rankings appear after the hunt finishes.
- The public roster contains only the username, current accepted amount, original acceptance and latest-edit timestamps, whether Twitch sign-in was verified, and a viewer-specific own-entry flag. Legacy unverified historical entries are labelled separately. Twitch account IDs, request IDs and abuse-prevention hashes are never part of the public roster. The signed-in owner's own response includes a revision identifier to prevent stale edits from replacing a newer guess.
- In `/admin?view=hunts`, Start opening bonuses changes phase and closes predictions in one conditional save. Back to hunting returns the active opening hunt to collection and explicitly reopens predictions in a fresh window, preserving saved guesses and payouts. Completed hunts stay final. Ordinary edits, imports, deactivation/removal and ID reuse cannot reopen a closed window. The public hunt response exposes read-only per-hunt prediction-window status and its cycle identifier, separate from editable hunt state.
- Predictions are recorded in the hunt's currency. If it changes after entries arrive, those entries cannot be ranked in the new currency; they resume only if the original currency is restored before predictions close. Setting up a fresh hunt's currency remains available.

## Storage and integration

`hunt-predictions.mjs` uses the existing Netlify Blobs integration. Predictions have their own per-hunt records so submissions do not change the editor's hunt revision or collide with normal hunt saves. Conditional writes, expected prediction revisions and bounded saved-version history handle simultaneous edits, duplicate retries and closure races. Only versions admitted within an accepted prediction window count, so late edits cannot erase a previously accepted guess or become eligible when predictions reopen. The latest accepted save time determines tie order. Preview storage is separated from production.

The existing session signing secret protects Twitch session cookies and encrypts server-side access tokens. The app also needs TWITCH_CLIENT_ID and TWITCH_CLIENT_SECRET, available only to Netlify Functions. No raw IP address, OAuth token or stream overlay token is returned by the predictions endpoint. See `docs/twitch-predictions-setup.md` for registration and activation.

The prediction script loads once per selected hunt/status, after a save, or when Refresh predictions is pressed. An unfinished hunt's roster refreshes at most once every 60 seconds while its panel is visible; hidden tabs, panels outside the viewport, active edit forms and completed hunts do not poll for roster updates. The existing hunt refresh propagates closure and explicit reopening without extra fast polling. A fresh window identifier prevents earlier-cycle requests and responses from changing a reopened prediction. Every eligible entry is available in a four-row scroll area, which moves only down, resets to the top and pauses for two seconds. Hover, keyboard focus, manual controls and reduced-motion preferences pause automatic motion. The signed-in viewer's saved amount remains in a separate fixed card and becomes locked once entries close. Signed-in viewers receive an approximately hourly session check, with hidden tabs checked on return, to meet Twitch token-validation requirements. Its mount and typed draft survive ordinary hunt updates. Hunt switches dispose scroll/refresh timers, and private/unavailable responses clear cached prediction data.

This update does not add homepage links or change the stream overlay.
